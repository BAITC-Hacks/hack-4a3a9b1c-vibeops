### Исправление замечаний Нурбола

- Цитаты выбираются совместно для всей выдачи. Приоритет имеют факты из своего профиля, отсутствующие в описаниях соседних карточек; одинаковое основание заменяется другим проверяемым фактом, если он есть. Сравнение игнорирует регистр, пунктуацию и анонимизированные имена. Подстановка имени не считается содержательным различием.
- Общая проверка применяется и к fallback, и к ответам LLM. Цитата, заменённая локальным алгоритмом, помечается `fallback`, а не `llm`. Если описание не даёт отдельного отличия, об этом прямо сказано в карточке; различия не выдумываются.
- Расширены признаки подарков, ансамблей, церемониймейстеров и видеографов. Неизвестные словарю содержательные предложения могут сохраниться. Фильтр всё ещё эвристический: это не универсальная семантическая оценка.
- Исправлено ложное совпадение «впечатлений» с «печатью». Длинные списки брендов исключаются из вариантов, когда есть другие факты.
- В воспроизводимом запросе Алматы / Лайв-бэнд / свадьба / 23.09.2026 / 6 млн ₸ первая группа описывается составом с двумя вокалистами и вокалисткой, вторая — четырьмя вокалистами и струнным квартетом. У HK-90005 доступны именные открытки, карточки рассадки, welcome-боксы и сладости.

## Конфигурация и SDK

- `OPENAI_API_KEY` — серверный ключ; `OPENAI_MODEL` — явно заданная модель.
- Живой batch подтверждён на `gpt-4.1-mini` 23.09.2026 около 13:32 UTC+5.
- Окружение загружает общий entrypoint сервера (dotenv или Node `--env-file`), сам модуль `.env` не читает.
- Responses API, `text.format.type=json_schema`, strict schema `{items:[{id,quote}]}`, `store:false`, максимум 1200 выходных токенов.
- Один запрос на весь набор карточек, SDK `maxRetries:0`. Общий deadline 6000 мс, AbortController + Promise.race; задержку остального backend учитывать отдельно.
- Модель и ключ не зашиты в код; ключи не выводятся в диагностику. Системный текст отделён от недоверенных строк описания/запроса, инструменты выполнения не подключены.

Официальные источники: [Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs), [GPT-4.1 mini](https://developers.openai.com/api/docs/models/gpt-4.1-mini). JSON Schema гарантирует форму, а факты проверяет наш код.

## Свидетельства и резервный режим

Версия промпта `firebird-evidence-v3`. Код выделяет до 60 непрерывных предложений/клауз на профиль длиной 18–220 Unicode-символов. Для длинных списков учитываются маркеры •; текст без пунктуации делится на непрерывные фрагменты по границам слов. JSON Schema anyOf связывает каждый id со своим enum дословных фрагментов (плюс пустая строка). Модель выбирает релевантное свидетельство из этих вариантов; свободное переписывание исключено схемой, серверная валидация сохранена. Это улучшение после live проверки v1, где модель перефразировала один профиль; такие ответы корректно попадали в fallback. Проверка нормализует Unicode NFC и пробелы, сохраняя регистр, цифры, слова и пунктуацию. Чужие ID отбрасываются, повторяющиеся ID не используются, цитата из другого профиля не проходит. Пустая/невалидная/отсутствующая цитата приводит к извлечению кодом для этой карточки.

Первое предложение собирается из структурированных полей: формат, дата, стартовая цена и бюджет, заданные язык/часы. Второе — атрибутированная цитата. `max_hours=null` не превращается в обещание неограниченной работы. Отсутствие даты в busy_dates не подтверждает бронирование. Стартовая цена не гарантирует итоговую стоимость — общую заметку об этом показывает UI.

Fallback разбивает описание на предложения/клаузы, выбирает конкретный фрагмент по маркерам формата, языка, услуг и опыта. Общая похвала может дать `quote:null`; факты каталога останутся. Это лексическая эвристика, **не LLM**. Фильтры и ranking принадлежат backend.

Каждая карточка имеет `source:llm|fallback`; весь результат — `llm|mixed|fallback|not_needed`. При полном fallback `model:null`. Ошибки провайдера преобразуются в безопасные русские предупреждения: отдельно 429, 401/403, таймаут, неверный ответ. Причина из сырого exception не публикуется.

Кэш: до 200 полностью проверенных LLM-ответов, LRU, TTL 10 минут. Ключ включает canonical query, SHA-256 CSV, модель, версию промпта и выбранных кандидатов. Ошибки/mixed не кэшируются; восстановившийся провайдер можно вызвать снова. Ответы клонируются, потребитель не меняет кэш. Кэш не обеспечивает и не меняет детерминизм ранжирования.
