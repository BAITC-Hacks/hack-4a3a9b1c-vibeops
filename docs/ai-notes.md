# AI-объяснения Firebird

Владелец: Арлан. Ветка `feat/explanations`. Модуль не фильтрует, не ранжирует и не запускает HTTP-сервер.

## Подключение Никите

Нужна серверная зависимость `openai@7.23.0` (эта версия проверена). Общие `package.json`, lockfile и `shared/contracts.ts` меняет Никита. Типы импортируются из `shared/contracts.js` по контракту v1 FIREBIRD-CODEX-PACK; расширение `.js` рассчитано на TypeScript NodeNext/tsx.

```ts
import { explainSelection, fallbackExplanation } from './explanations/index.js';

const selected = selection.ranked.slice(0, 3);
const explanations = await explainSelection({
  query: selection.query,
  candidates: selected,
  dataset_sha256: catalog.sha256,
});
const byId = new Map(explanations.items.map(item => [item.id, item]));
// Карточки собирать в порядке selected, соединяя по vendor.id.
// При дополнительном восстановлении через fallbackExplanation обновить общий mode.
```

`explainSelection` принимает не более 3 уникальных выбранных профилей. Ошибка границы означает ошибку вызывающего кода. Для пустого массива вернёт `not_needed` без обращения к API. `fallbackExplanation(query, candidate)` — синхронная функция.

## Конфигурация и SDK

- `OPENAI_API_KEY` — серверный ключ; `OPENAI_MODEL` — явно заданная модель.
- Живой batch подтверждён на `gpt-4.1-mini` 23.09.2026 около 13:32 UTC+5.
- Окружение загружает общий entrypoint сервера (dotenv или Node `--env-file`), сам модуль `.env` не читает.
- Responses API, `text.format.type=json_schema`, strict schema `{items:[{id,quote}]}`, `store:false`, максимум 1200 выходных токенов.
- Один запрос на весь набор карточек, SDK `maxRetries:0`. Общий deadline 6000 мс, AbortController + Promise.race; задержку остального backend учитывать отдельно.
- Модель и ключ не зашиты в код; ключи не выводятся в диагностику. Системный текст отделён от недоверенных строк описания/запроса, инструменты выполнения не подключены.

Официальные источники: [Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs), [GPT-4.1 mini](https://developers.openai.com/api/docs/models/gpt-4.1-mini). JSON Schema гарантирует форму, а факты проверяет наш код.

## Свидетельства и резервный режим

Версия промпта `firebird-evidence-v2`. Код выделяет до 60 непрерывных предложений/клауз на профиль длиной 18–220 Unicode-символов. JSON Schema anyOf связывает каждый id со своим enum дословных фрагментов (плюс пустая строка). Модель выбирает релевантное свидетельство из этих вариантов; свободное переписывание исключено схемой, серверная валидация сохранена. Это улучшение после live проверки v1, где модель перефразировала один профиль; такие ответы корректно попадали в fallback. Проверка нормализует Unicode NFC и пробелы, сохраняя регистр, цифры, слова и пунктуацию. Чужие ID отбрасываются, повторяющиеся ID не используются, цитата из другого профиля не проходит. Пустая/невалидная/отсутствующая цитата приводит к извлечению кодом для этой карточки.

Первое предложение собирается из структурированных полей: формат, дата, стартовая цена и бюджет, заданные язык/часы. Второе — атрибутированная цитата. `max_hours=null` не превращается в обещание неограниченной работы. Отсутствие даты в busy_dates не подтверждает бронирование. Стартовая цена не гарантирует итоговую стоимость — общую заметку об этом показывает UI.

Fallback разбивает описание на предложения/клаузы, выбирает конкретный фрагмент по маркерам формата, языка, услуг и опыта. Общая похвала может дать `quote:null`; факты каталога останутся. Это лексическая эвристика, **не LLM**. Фильтры и ranking принадлежат backend.

Каждая карточка имеет `source:llm|fallback`; весь результат — `llm|mixed|fallback|not_needed`. При полном fallback `model:null`. Ошибки провайдера преобразуются в безопасные русские предупреждения: отдельно 429, 401/403, таймаут, неверный ответ. Причина из сырого exception не публикуется.

Кэш: до 200 полностью проверенных LLM-ответов, LRU, TTL 10 минут. Ключ включает canonical query, SHA-256 CSV, модель, версию промпта и выбранных кандидатов. Ошибки/mixed не кэшируются; восстановившийся провайдер можно вызвать снова. Ответы клонируются, потребитель не меняет кэш. Кэш не обеспечивает и не меняет детерминизм ранжирования.

## Фактические проверки

23.09.2026: изолированная сборка в `/tmp` против точной копии контракта из пакета, OpenAI SDK 7.23.0. `tsc --noEmit` и 14 тестов `tsx --test tests/explanations/*.test.ts` прошли. После добавления общего каркаса: npm run build и все 17 тестов прошли также в чистой копии. Модуль компилируется с опубликованным shared/contracts.ts; вызов из /api/recommend ещё должен подключить Никита.

Тесты: пустая выдача без API; отсутствие конфигурации; один batch и сохранение порядка; чужие/повторные ID и чужая цитата; изменённые факты/длина/несколько предложений; неверная схема; 429/auth/500 без утечки исключения; deadline и abort; кэш/TTL/смена dataset и модели/лимит 200; null hours; нарушение входного контракта. SDK проверен с подменённым HTTP transport: правильный endpoint/schema и отсутствие retries на 429. Это **unit/provider-stub**, не живой AI.

Ручная проверка D1 на исходном CSV (отдельно вычисленная выборка): HK-88430, HK-27222, HK-29829. Fallback-цитаты различимы без имён: корпоративы/деловые встречи; сотрудничество с перечисленными брендами; развлечения и танцы. Это содержимое профилей, не независимо подтверждённые факты. Смена даты и исключения — задача backend/UI.

Live D1 на v2: 3799 мс холодный запрос, все 3 source=llm, mode=llm, warning=null; повтор 0 мс после округления (менее 1 мс), cached=true. Реальные цитаты: корпоративы/деловые встречи; сотрудничество с перечисленными брендами; развлечения и танцы. Проверены принадлежность источнику и различимость без имён. Это один успешный замер модуля, не SLA и не скорость полного UI/API.

Осталось: подключение подбора и сквозная проверка UI/API; доступ жюри к серверному AI. Создание ключа и наличие кредитов не доказательство успешного вызова. Ограничения: проверка принадлежности цитаты не доказывает её смысловую релевантность или истинность; LLM-цитаты между холодными запусками могут различаться, порядок подрядчиков — нет.

Для жюри нужен настроенный серверный ключ через согласованный канал или демонстрационный сервер. Без ключа приложение сохраняет объяснения на реальных данных, но показывает fallback; это не подмена live AI.
