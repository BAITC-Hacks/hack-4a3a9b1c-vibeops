Пока эта сборка идёт, локальный старый main ещё не содержит новые валюты/даты: фиксировать SHA, не путать ожидаемую незавершённость с регрессией. Как только опубликован релизный SHA — повторить проверки на нём. Правки каждого отдельной веткой и PR, только свои файлы; чужие незакоммиченные изменения сохранять. Commit+push содержательного результата хотя бы каждый час.

## Что Никита проверяет

1. Чистая копия → npm ci → env → build → start. Не использовать неучтённые файлы с ноутбука Арлана.
2. Без ключа: health и ручной поиск/fallback; помощник сообщает об отсутствии доступа.
3. С согласованным серверным ключом: настоящий brief → recommend → compare; статус источника, задержка, отказ API.
4. README соответствует командам; путь CSV, диапазон календаря и цена «от» понятны. По разрешённому каналу подготовлен доступ жюри.
5. На итоговом SHA повторить D1–D6, API альтернатив и неизменность CSV; сообщить проверенный SHA.

## Что Нурбол проверяет

1. «Нужна свадьба в Алматы послезавтра» — дата распознана, неизвестные категория/бюджет уточняются.
2. «Нужен ведущий на свадьбу в Алматы послезавтра, бюджет 500 долларов» — точная дата и приблизительная сумма с курсом показаны до подтверждения.
3. «100 гостей» без суммы — бюджет не придуман; с отдельным бюджетом — число гостей не подменяет его.
4. Исправить дату, бюджет и пожелания; начать ввод во время ожидания; перейти к демо/ручной форме; сбросить диалог. Старый ответ не возвращает старые условия.
5. Отказ сравнения не убирает найденные карточки; есть понятная повторная попытка.
6. Применить альтернативу даты/бюджета: изменилось одно поле, остальные условия и пожелания сохранились, карточки/сравнение обновились.
7. Подарки и группы из отчёта качества; неизвестная категория; никто не подходит; длинные цитаты и небольшой экран.

Формат дефекта: SHA → текст запроса и последовательность кликов → ожидание → фактический результат → повторяемость. Ключи, cookies и личные данные в отчёт не включать.
