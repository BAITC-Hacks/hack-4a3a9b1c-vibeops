# Локальная демонстрация Firebird

## Перед показом

1. Сохранить текущую работу и забрать актуальный main. Не выполнять reset/force для обновления.
2. Из корня: `npm ci`, `npm run build`. Для первой установки скопировать `.env.example` в `.env`; существующий `.env` не перезаписывать.
3. `npm start`; открыть `http://localhost:3000`. Открывать приложение через сервер, не client/index.html и не Live Server.
4. Для настоящего AI должны быть заданы серверные `OPENAI_API_KEY` и `OPENAI_MODEL`. `/api/health` показывает наличие конфигурации; успешность вызова подтверждается только полученными карточками с источником AI.
5. Во втором терминале: `node tests/ui/acceptance.mjs`. Ожидается PASS. Если режим fallback — данные настоящие, но LLM в этом запуске не подтверждён.

Не менять исходники перед показом ради запуска. Не показывать .env, терминал с ключом или страницу создания ключей на общем экране. При смене машины конфигурацию доступа согласовать отдельно; Git содержит только пустой пример.

## Рассказ и показ на 2–3 минуты

**Задача:** человек уже знает город, формат и бюджет, но длинный каталог не объясняет различия между подрядчиками. Firebird сокращает выбор до трёх и показывает проверяемые основания.

1. **D1:** Алматы, ведущий, корпоратив, 10 октября, 1 млн ₸. Показать три карточки: разные основания, стартовую цену, источник объяснения. Пояснить, что занятые и неподходящие исключены до вызова AI.
2. **D2:** сменить только дату на 11 октября. Состав меняется: Куррапика занят, Буллма проходит. Открыть причины занятости — изменение связано с календарём, не случайной выдачей модели.
3. **D3:** один флорист. Показать, почему карточка одна: всего два профиля, один занят. Не дополняем выдачу выдуманными подрядчиками.
4. **D4 и D5:** явно показать разницу «категории нет в городе» и «категория есть, условия никто не прошёл».
5. **D6:** банкетный зал использует те же условия и календарь, что люди.

**Техническое объяснение:** код проверяет условия и формирует устойчивый порядок; AI выбирает конкретные фрагменты описаний из ограниченной схемы; сервер проверяет принадлежность цитаты источнику. При недоступности AI сохраняется рабочий каталог и показывается честный fallback. Цена «от», отсутствие отметки занятости не означает подтверждённого бронирования.

**Ограничения:** 66 анонимизированных профилей, календарь до 31 декабря; часть значений дополнена организатором и помечена. Ranking — прозрачная эвристика, не обученная оценка качества. Экономию времени/конверсию пока не измеряли, не придумывать эти показатели.

**Дальнейшее развитие как план:** обновление календарей из систем подрядчиков, подтверждение окончательной стоимости, оценка качества выбора на пользовательских данных. Не представлять планы уже реализованными функциями.
