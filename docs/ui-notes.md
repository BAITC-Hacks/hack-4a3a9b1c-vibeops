# Интерфейс Firebird

Владелец: Нурбол. Ветка: `feat/ui`. Контракт: раздел 5 FIREBIRD-CODEX-PACK.md, v1.

## Подключение к каркасу Никиты

- `client/index.html` — вход Vite; `client/src/main.tsx` — React entry.
- Frontend импортирует типы `Query`, `Card`, `Reason`, `RecommendResponse`, `ApiError` из `shared/contracts.ts` в корне. Эти типы должен экспортировать общий контракт Никиты.
- Runtime-зависимости: `react`, `react-dom`. Build-зависимости: `vite`, `typescript`, типы React/React DOM. Дополнительных UI-библиотек нет. Общими package.json, lockfile и конфигурацией владеет Никита.
- Рекомендуемая настройка Vite: `root: 'client'`, dev proxy `/api` на backend, `build.outDir: '../dist/client'`. Express раздаёт этот каталог и index.html в production. Это требование интеграции, не утверждение о готовом общем запуске.
- TypeScript: DOM libs, `jsx: react-jsx`. Единственный импорт внешних типов — общий контракт.
- Запросы same-origin: `GET /api/options`, `POST /api/recommend`. CSV, фильтрация, ранжирование и ключи на клиенте отсутствуют.

## Реализованные состояния

Форма содержит все пять обязательных полей, опциональные язык/часы. Options приходят с сервера, категории глобальные. Дата ограничена окном сервера, бюджет допускает 0, пустые язык/часы уходят как null.

Три outcome различимы словами. Карточки отображаются в порядке API, максимум 3; цена обозначена «от», max_hours=null обозначен как неприменимость часов присутствия. Показаны synthetic/imputed, объяснение, источник и цитата. Нет бронирования или обещания окончательной цены.

При смене поля предыдущий запрос отменяется, результат очищается. Request sequence дополнительно защищает от устаревшего ответа. Submit заблокирован во время запроса; демо позволяют сменить запрос и отменить предыдущий. Timeout клиента 15 секунд — защита от зависшего соединения, не обещание выполнения ориентира DoD до 10 секунд.

Ошибка сервера/сети отображается отдельно от no_matches. Режимы fallback/mixed и warning видимы. Причины исключения показаны с пересекающимися счётчиками и отдельным числом исключённых профилей. Поимённая занятость показывается для даты результата.

Демо D1–D6 содержат только параметры запросов из пакета. Результаты всегда поступают от backend. Все строки из API выводятся средствами React как текст, без HTML-вставок.

### Как повторить UI-тесты после интеграции

После добавления общих зависимостей и shared/contracts.ts владельцем backend:

```sh
# Дополнительные devDependencies для тестов (добавляет владелец package.json):
npm install --save-dev vitest jsdom @testing-library/react
npx vitest run --config tests/ui/vitest.config.mts
```

Конфигурация тестов изолирована от общего Vite config. Tests импортируют реальный client/src/App.tsx. Fixtures в tests/ui используются только тестами и не включаются в клиентскую сборку.

Возможность live AI, реальный ranking и правильность причин исключения проверяются совместно с backend после первой интеграции. Фронтенд не исправляет и не пересортировывает выдачу сервера.
