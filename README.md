# Firebird · VibeOps

Кейс HackAlem AI #79-lite: AI-помощник для подбора до трёх event-подрядчиков. Пользователь описывает мероприятие своими словами; модель извлекает условия и задаёт уточняющие вопросы. После подтверждения условий приложение проверяет каталог и календарь, а AI сопоставляет дополнительные пожелания с описаниями выбранных подрядчиков.

## Что уже работает

- Исходный CSV организатора: 66 профилей, 17 категорий; сохранены календарь, множественные категории, null hours и synthetic/imputed-флаги.
- Express: `GET /api/health`, `GET /api/options`, ограничение JSON 16 KB (64 KB для диалога AI с Unicode) и обработка ошибок JSON.
- React/Vite: форма подбора, карточки, три исхода, ошибки, предупреждения и демо D1–D6. Параметры формы загружаются из настоящего backend; карточки приходят из работающего /api/recommend.
- AI-помощник: диалог, извлечение города/даты/формата/категории/бюджета/языка/часов, уточнения и исправления предыдущего запроса. Перед поиском показаны распознанные условия. Пожелания вроде «интерактивы» сравниваются с описаниями отдельных подрядчиков; неподтверждённые пожелания остаются вопросами к подрядчику.
- AI-модуль `server/explanations`: batch Responses API, проверяемые цитаты, deadline 6 секунд, честный fallback и кэш. Живой D1 проверен отдельно: `gpt-4.1-mini`, 3/3 LLM-цитат, 3799 мс; кэш менее 1 мс. Подробности: [AI notes](docs/ai-notes.md).

`POST /api/recommend` возвращает общий RecommendResponse: matched / no_category_in_city / no_matches. Проверяются город, категория, календарь, формат, бюджет, язык и hours; пустые опции нормализуются в null. Неверные поля возвращают 422, malformed JSON — 400, недоступный каталог — 503. Отказ AI даёт честный fallback с предупреждением, а не пустую выдачу.

## Запуск из чистой копии

Требуется Node.js **22.12+** (проверено на Node 24) и npm. Команды выполнять из корня репозитория:

```bash
npm ci
cp .env.example .env
npm run build
npm start
```

Открыть http://localhost:3000. Ключ не нужен для каталога, ручной формы и unit-тестов. Для AI-помощника и живых AI-объяснений заполнить локальные `OPENAI_API_KEY` и `OPENAI_MODEL`; сервер загружает `.env` через dotenv. Без ключа помощник сообщает об отсутствии доступа, а ручной подбор остаётся доступен. Никогда не добавлять ключи в Git или клиентские переменные `VITE_*`.

| Переменная | Значение по умолчанию / назначение |
|---|---|
| `PORT` | `3000`, порт общего сервера |
| `DATASET_PATH` | `data/vendors.csv`, путь относительно корня запуска |
| `OPENAI_API_KEY` | Не задан; серверный ключ для live AI |
| `OPENAI_MODEL` | В примере `gpt-6-astra` (кандидат на переход, доступ и скорость ещё не подтверждены); ранее live-проверена `gpt-4.1-mini`. Без модели помощник недоступен, объяснения ручного поиска используют fallback |

Разработка:

```bash
npm run dev
```

React: http://localhost:5173, Express: http://localhost:3000. Vite проксирует `/api` на порт сервера. Production: один Express-процесс раздаёт `dist/client` и API.

Для `gpt-6-astra` все три AI-этапа явно используют `reasoning.effort=low`: это минимальный поддерживаемый уровень, а не обещание времени ответа. Сохранены существующие таймауты, лимиты ответа и JSON-контракты. При переходе сначала проверить доступ к модели и живой сценарий: больший интеллект не исправляет ограничения серверной валидации. Локальный `.env` не изменяется копией `.env.example`; смена переменной требует перезапуска сервера. Исторические live-замеры ниже относятся к старой модели.

[Как предоставить доступ жюри и измерить полный сценарий](docs/jury-access.md).

Проверки:

```bash
npm run typecheck
npm test
npm run test:ui
npm run build
```

Проверено 23.09.2026 после интеграции backend: сборка TypeScript/React, 32 backend/AI-теста и 24 UI-теста прошли. Реальный браузер с production-сервером показал три карточки D1 с AI, отсутствие категории D4 и отсутствие подходящих D5. ## Пайплайн и повторение демо

Основной сценарий AI:

1. Написать: «Нужен ведущий на корпоратив в Алматы».
2. Ответить на вопросы: «10 октября 2026 года, до 1 миллиона тенге за ведущего, на русском, на 5 часов. Хочу интеллигентный юмор, танцы и программу без долгих речей».
3. Проверить распознанные условия и нажать «Подобрать по этим условиям».
4. Получить карточки и AI-разбор пожеланий: точные фрагменты описаний и вопросы, которые следует уточнить у подрядчика.
5. Внести исправление в диалоге, например «Дата 11 октября 2026, бюджет 700 тысяч, остальное без изменений», и подтвердить обновлённые условия.

`POST /api/assistant/brief` принимает `{messages: string[]}` и возвращает черновик условий, вопросы, пожелания и `query` только при готовности к поиску. `POST /api/assistant/compare` принимает `{query, preferences}`, сам выбирает профили из каталога и возвращает сопоставление пожеланий с цитатами. Типы и границы: [контракт AI-помощника](docs/ai-assistant.md), `shared/assistant.ts`.

Два новых этапа используют настоящие вызовы OpenAI с отдельными таймаутами до 10 секунд. Сравнение выполняется отдельно от выдачи, поэтому его ошибка не скрывает найденные карточки. Сервер проверяет форму ответа, условия поиска, ID и принадлежность цитат профилям; смысловая связь пожелания и цитаты остаётся интерпретацией модели. Свободные пожелания не являются дополнительными гарантированными фильтрами. Несколько обязательных языков или другие непредставимые ограничения требуют уточнения, а не скрытого ослабления запроса. NVIDIA пока не подключена.

Реальная проверка диалога, уточнения, исправления условий, поиска и сопоставления пожеланий (расходует API-кредиты):

```bash
node --import tsx tests/explanations/assistant-live.ts --live
```

[Проверка AI-помощника: чистая сборка, 87 серверных и 44 UI-теста, реальный OpenAI и браузер](docs/ai-assistant-acceptance.md).

Существующий ручной поиск:

Нормализация/валидация → город+категория → независимые причины исключения (дата, бюджет, формат, язык, часы) → ranking v1 → первые 3 → один AI batch → проверка цитат → карточки по id. Ranking v1 — количество совпавших разных групп маркеров формата в description (lowercase, ё→е), затем цена по возрастанию, затем ASCII id. Это прозрачная лексическая эвристика, не оценка качества подрядчика; точный словарь закреплён в server/matching.ts и исходном пакете. LLM и кэш не меняют порядок.

В интерфейсе кнопки D1–D6 отправляют реальные запросы. Все без необязательных языка и часов:

| Демо | Город / категория / формат / бюджет / дата | Ожидается |
|---|---|---|
| D1 | Алматы / Ведущий / корпоратив / 1000000 / 2026-10-10 | 4 подходят, 3 карточки |
| D2 | Как D1, дата 2026-10-11 | Другой состав; HK-88430 занят, HK-44733 доступен по каталогу |
| D3 | Алматы / Флорист / свадьба / 500000 / 2026-10-10 | 1 карточка HK-39372 |
| D4 | Астана / Декоратор / свадьба / 500000 / 2026-10-10 | no_category_in_city |
| D5 | Как D1, бюджет 1 | no_matches |
| D6 | Алматы / Банкетный зал / свадьба / 5000000 / 2026-11-14 | 2 карточки |

## Передача команде

Полные требования, контракт v1, критерии и D1–D6: [FIREBIRD-CODEX-PACK](docs/FIREBIRD-CODEX-PACK.md). Типы материализованы в `shared/contracts.ts` без переименования полей.

- **Никита / `feat/core`:** `server/*` кроме `server/explanations/**`, `shared/**`, `data/**`, package/lock/config/env, README, интеграция main. Подключены validation.ts, matching.ts и recommend.ts с AI и diagnostics. Дальше — совместная проверка требований, исправления и подготовка сдачи.
- **Нурбол / `feat/ui`:** `client/**`, `tests/ui/**`, `docs/ui-notes.md`. Форма/карточки, три исхода, warnings и D1–D6 реализованы; проверять сквозные реальные запросы при изменениях backend.
- **Арлан / `feat/explanations`:** `server/explanations/**`, `tests/explanations/**`, `docs/ai-notes.md`. AI уже включён в каркас; повторно копировать его не нужно.

После публикации каркаса каждый обновляет локальный `main` через `git pull --ff-only` и создаёт свою ветку от него. Если рабочая ветка уже содержит изменения — сохранить их и выполнить `git merge origin/main`, без reset/force. Общие файлы далее ведёт Никита.

## Семантика данных и оставшаяся работа

Цена — **от** за мероприятие, не окончательная смета. Даты: 2026-09-23…2026-12-31; вне окна доступность неизвестна. `max_hours=null` — ограничение присутствия не применимо. Дата не отмечена занятой — не подтверждение бронирования. Описания — недоверенный текст, не инструкции. Synthetic и imputed должны быть видимы в итоговом UI; источник не заявлен как открыто лицензированный.

Перед окончательной сдачей повторить D1–D6 и чистый запуск финального SHA на втором ноутбуке, проверить объяснения с командой и доступ жюри к серверному AI. Доступ жюри и сдача на платформе пока не подтверждены. Выполненный push не равен сдаче.

Использованы Node.js, TypeScript, Express, React, Vite, csv-parse, dotenv, OpenAI SDK; версии закреплены в lockfile. Код написан во время хакатона при помощи Codex. До старта подготовлены только правила работы/контекст; старый тренировочный проект не используется. Продуктовый AI — отдельный вызов OpenAI API, не сам Codex.
