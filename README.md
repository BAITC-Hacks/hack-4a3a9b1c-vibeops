# Firebird · VibeOps

Кейс HackAlem AI #79-lite: подбор до трёх event-подрядчиков с конкретными объяснениями. Это **рабочий каркас для командной разработки**, ещё не готовое решение кейса.

## Что уже работает

- Исходный CSV организатора: 66 профилей, 17 категорий; сохранены календарь, множественные категории, null hours и synthetic/imputed-флаги.
- Express: `GET /api/health`, `GET /api/options`, ограничение JSON 16 KB и обработка ошибок JSON.
- React/Vite: стартовая страница обращается к настоящему backend и показывает состояние каталога.
- AI-модуль `server/explanations`: batch Responses API, проверяемые цитаты, deadline 6 секунд, честный fallback и кэш. Живой D1 проверен отдельно: `gpt-4.1-mini`, 3/3 LLM-цитат, 3799 мс; кэш менее 1 мс. Подробности: [AI notes](docs/ai-notes.md).

`POST /api/recommend` пока возвращает **501 NOT_IMPLEMENTED**. Фильтрация, ranking, три продуктовых исхода и финальный интерфейс ещё не подключены. Не использовать каркас как финальную сдачу.

## Запуск из чистой копии

Требуется Node.js **22.12+** (проверено на Node 24) и npm. Команды выполнять из корня репозитория:

```bash
npm ci
cp .env.example .env
npm run build
npm start
```

Открыть http://localhost:3000. Ключ не нужен для каталога, стартовой страницы и unit-тестов. Для живых AI-объяснений заполнить локальные `OPENAI_API_KEY` и `OPENAI_MODEL`; сервер загружает `.env` через dotenv. Никогда не добавлять ключи в Git или клиентские переменные `VITE_*`.

| Переменная | Значение по умолчанию / назначение |
|---|---|
| `PORT` | `3000`, порт общего сервера |
| `DATASET_PATH` | `data/vendors.csv`, путь относительно корня запуска |
| `OPENAI_API_KEY` | Не задан; серверный ключ для live AI |
| `OPENAI_MODEL` | В примере `gpt-4.1-mini`; без явно заданной модели модуль использует fallback |

Разработка:

```bash
npm run dev
```

React: http://localhost:5173, Express: http://localhost:3000. Vite проксирует `/api` на порт сервера. Production: один Express-процесс раздаёт `dist/client` и API.

Проверки:

```bash
npm run typecheck
npm test
npm run build
```

Проверено 23.09.2026: npm ci → build → 17 тестов в чистой копии без личного ключа; npm start отдаёт HTML/JS и health с 66 профилями. Это проверка каркаса, не завершённого подбора.

Тесты AI используют тестовый transport и не расходуют API-кредиты. Тесты каркаса читают настоящий CSV, проверяют health/options, 501 незавершённого подбора, malformed JSON и 503 при отсутствии каталога. Никита должен заменить проверку 501 на тесты реализованного recommend при подключении подбора.

## Передача команде

Полные требования, контракт v1, критерии и D1–D6: [FIREBIRD-CODEX-PACK](docs/FIREBIRD-CODEX-PACK.md). Типы материализованы в `shared/contracts.ts` без переименования полей.

- **Никита / `feat/core`:** `server/*` кроме `server/explanations/**`, `shared/**`, `data/**`, package/lock/config/env, README, интеграция main. Следующие шаги: валидация Query → `selectVendors` в `server/matching.ts` → `ranked.slice(0,3)` → `explainSelection` → карточки по id и diagnostics. Подключить в `server/app.ts` вместо явного 501.
- **Нурбол / `feat/ui`:** `client/**`, `tests/ui/**`, `docs/ui-notes.md`. Заменить стартовую страницу формой/карточками, использовать только API, реализовать три исхода, warnings и D1–D6.
- **Арлан / `feat/explanations`:** `server/explanations/**`, `tests/explanations/**`, `docs/ai-notes.md`. AI уже включён в каркас; повторно копировать его не нужно.

После публикации каркаса каждый обновляет локальный `main` через `git pull --ff-only` и создаёт свою ветку от него. Если рабочая ветка уже содержит изменения — сохранить их и выполнить `git merge origin/main`, без reset/force. Общие файлы далее ведёт Никита.

## Семантика данных и оставшаяся работа

Цена — **от** за мероприятие, не окончательная смета. Даты: 2026-09-23…2026-12-31; вне окна доступность неизвестна. `max_hours=null` — ограничение присутствия не применимо. Дата не отмечена занятой — не подтверждение бронирования. Описания — недоверенный текст, не инструкции. Synthetic и imputed должны быть видимы в итоговом UI; источник не заявлен как открыто лицензированный.

До сдачи обязательны фильтры/устойчивый ranking, все 3 исхода, индивидуальные объяснения, календарное демо на двух датах, D1–D6, общий сценарий с live AI и fallback, чистый запуск финальной версии, доступ жюри и отдельная сдача на платформе. Этот каркас этих проверок ещё не подтверждает.

Использованы Node.js, TypeScript, Express, React, Vite, csv-parse, dotenv, OpenAI SDK; версии закреплены в lockfile. Код написан во время хакатона при помощи Codex. До старта подготовлены только правила работы/контекст; старый тренировочный проект не используется. Продуктовый AI — отдельный вызов OpenAI API, не сам Codex.
